## ❌ 영어 끝말잇기 — 중복 확인과 반복문 종료

- 문제: 끝말잇기에서 가장 먼저 탈락하는 사람의 번호와 그 사람의 몇 번째 차례인지 구한다.
- 실수 1: 중복 단어를 찾은 뒤 `break`를 사용했지만 안쪽 반복문만 종료되어 뒤의 탈락 위치로 결과가 바뀔 수 있었다.
- 해결 1: 중복을 찾았다면 바깥 반복문도 종료하거나 함수에서 바로 반환한다.
- 실수 2: 발언 순서를 1부터 세면서 나머지를 차례 계산에도 더했다.
- 해결 2: 0부터 시작하는 인덱스 `i`를 사용하면 사람 번호는 `i % n + 1`, 자신의 차례는 `i // n + 1`이다.

| 기준 | 사람 번호 | 자신의 차례 |
| --- | --- | --- |
| 0부터 시작하는 인덱스 `i` | `i % n + 1` | `i // n + 1` |
| 1부터 시작하는 발언 순서 `r` | `(r - 1) % n + 1` | `(r - 1) // n + 1` |

```python
def solution(n, words):
    used = set()

    for i, word in enumerate(words):
        if word in used or (i > 0 and words[i - 1][-1] != word[0]):
            return [i % n + 1, i // n + 1]
        used.add(word)

    return [0, 0]
```

**기억할 규칙:** `break`는 가장 가까운 반복문 하나만 끝낸다. 중복 여부만 빠르게 확인할 때는 이미 나온 단어를 `set`에 저장한다.

## ❌ 오픈채팅방 — 닉네임 관리와 입퇴장 기록 분리

- 학습 상태: **풀이 참고 · 재풀이 필요**
- 제출 상태: 통과 여부 미확인
- 문제: 입장·퇴장 메시지를 각 사용자의 최종 닉네임으로 출력한다. 닉네임 변경 자체는 메시지를 남기지 않는다.

| 실수하거나 막힌 부분 | 원인과 수정 방향 |
| --- | --- |
| 모든 기록에서 `values[2]`에 접근 | `Leave`에는 행동과 ID만 있으므로 기록 종류에 따라 접근 위치를 구분한다. |
| 기존 ID가 있으면 입장 기록을 추가하지 않음 | 재입장도 새로운 입장이므로 닉네임 수정과 기록 추가를 별개로 처리한다. |
| 닉네임 수정 후 `break`로 종료 | 같은 ID의 모든 메시지에는 최종 닉네임이 적용되어야 한다. |
| 반복 변수에 새 이름을 대입 | 반복 변수만 바뀌고 원래 리스트는 수정되지 않는다. |
| `Leave`마다 닉네임을 검색 | 사건의 순서와 최종 사용자 정보를 분리해 저장한다. |

### 개선 방향

- 로그에는 입장·퇴장 행동과 사용자 ID만 순서대로 저장한다.
- 딕셔너리에는 사용자 ID를 키로, 최종 닉네임을 값으로 저장한다.
- `Enter`와 `Change`에서 닉네임을 갱신한다.
- `Enter`와 `Leave`만 메시지용 로그에 추가한다.
- 모든 기록을 처리한 뒤 최종 닉네임으로 메시지를 만든다.

**기억할 규칙:** 발생한 사건의 순서와 나중에 바뀔 수 있는 사용자 정보를 분리해서 저장한다.

### 재풀이 확인 사항

- [ ] 완성 코드를 보지 않고 딕셔너리 방식으로 직접 작성하기
- [ ] 퇴장 후 다른 닉네임으로 재입장해도 모든 메시지에 최종 이름이 반영되는지 확인하기
- [ ] 닉네임 변경 자체에는 메시지가 생기지 않는지 확인하기
- [ ] 서로 다른 ID가 같은 닉네임을 사용해도 구분되는지 확인하기
- [ ] 직접 제출한 결과를 확인한 뒤 제출 상태 갱신하기
