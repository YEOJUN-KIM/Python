### ❌ 01 · 소수 만들기 — 조합의 중복과 합의 중복을 혼동

- 문제: `nums`에서 서로 다른 3개를 골라 더했을 때 소수가 되는 경우의 개수를 구한다.
- 실수: `answer = sorted(set(answer))`로 같은 합을 제거했다.
- 원인: “서로 다른 3개”를 합도 서로 달라야 한다는 뜻으로 이해했다. 실제로는 한 조합 안에서 같은 원소를 다시 고르지 않는다는 뜻이다.
- 해결: 합이 같아도 서로 다른 조합이면 각각 세므로 `set()`을 사용하지 않는다. 정렬도 필요하지 않다.
- 기억할 규칙: “경우의 개수”와 “서로 다른 결과 값의 개수”를 구분한다. `i < j < k`는 같은 위치 조합의 중복을 막지만 합의 중복까지 막지는 않는다.
- 중복 제거가 필요한 경우: 문제에서 서로 다른 합만 요구할 때는 `set(answer)`를 사용하고, 오름차순 정렬까지 요구할 때는 `sorted(set(answer))`를 사용한다.

예를 들어 `[1, 2, 3, 4, 6]`에서 `1 + 4 + 6`과 `2 + 3 + 6`은 모두 소수 `11`을 만들지만 서로 다른 조합이므로 각각 센다.

#### 반복문으로 3개의 합 구하기

`i`, `j`, `k`는 값이 아니라 위치다. 항상 `i < j < k`가 되게 골라 같은 위치 조합을 중복해서 고르지 않는다.

- `i`: 뒤에 두 원소가 남아 있어야 하므로 `len(nums) - 2` 직전까지 순회한다.
- `j`: `i + 1`부터 시작하고 뒤에 한 원소를 남긴다.
- `k`: `j + 1`부터 마지막 원소까지 순회한다.
- 배열 길이가 늘어나도 3개를 고르는 코드의 구조는 같다.

```python
def solution(nums):
    answer = []
    result = 0

    for i in range(len(nums) - 2):
        for j in range(i + 1, len(nums) - 1):
            for k in range(j + 1, len(nums)):
                answer.append(nums[i] + nums[j] + nums[k])

    for value in answer:
        bol = True
        for divisor in range(2, value):
            if value % divisor == 0:
                bol = False
                break
        if bol:
            result += 1

    return result
```

직접 작성한 소수 판별 방법은 이 문제에서 맞다. `break`는 약수를 찾았을 때 불필요한 검사를 끝내는 개선이다. 일반적인 소수 판별에서는 2 미만도 제외해야 하지만, 이 문제의 세 수의 합은 항상 2보다 크다.

#### 모범답안 · `itertools.combinations` 사용

`combinations(nums, 3)`은 순서에 상관없이 서로 다른 위치의 원소 3개를 고르는 모든 조합을 만든다. `sum(group)`으로 각 조합의 합을 구한다.

```python
from itertools import combinations
from math import isqrt


def solution(nums):
    result = 0

    for group in combinations(nums, 3):
        value = sum(group)
        is_prime = True

        for divisor in range(2, isqrt(value) + 1):
            if value % divisor == 0:
                is_prime = False
                break

        if is_prime:
            result += 1

    return result
```

소수가 아닌 수는 약수 쌍 중 하나가 제곱근 이하이므로 제곱근까지만 검사해도 된다. `isqrt(value)`는 제곱근의 정수 부분이며, `range()`의 끝은 제외되므로 `+ 1`을 붙인다. 합을 별도 리스트에 모으지 않고 조합마다 바로 판별해 센다.

### ❌ 02 · 영어 끝말잇기 — 반복문 종료와 차례 계산

- 문제: 끝말잇기에서 가장 먼저 탈락하는 사람의 번호와 그 사람의 몇 번째 차례인지 구한다.
- 실수 1: 중복 단어를 찾은 뒤 `break`를 사용했지만 안쪽 `for j`만 종료되어, 바깥 반복문에서 뒤의 탈락 위치로 `result`가 바뀔 수 있었다.
- 해결 1: 중복을 찾았다면 바깥 반복문도 종료한다. 함수에서 바로 `return`하는 방법도 있다.
- 실수 2: `result += 1`로 발언 순서를 1부터 세도록 바꾼 뒤, 나머지가 있을 때 차례를 `result // n + result % n`으로 계산했다.
- 해결 2: 나머지가 있으면 차례는 `result // n + 1`이다. 나머지는 사람 번호를 구하는 데 쓰이며 차례에 더하지 않는다.
- 추가 주의: `/`는 실수를 반환하므로 정수 차례 계산에는 `//`를 사용한다.

**1부터 생각한 것 자체가 실수는 아니다.** 인덱스 또는 발언 순서 중 어떤 기준을 쓰는지 정하고 그 기준에 맞는 계산식을 사용한다.

| 기준 | 사람 번호 | 자신의 차례 |
| --- | --- | --- |
| 0부터 시작하는 인덱스 `i` | `i % n + 1` | `i // n + 1` |
| 1부터 시작하는 발언 순서 `r` | `(r - 1) % n + 1` | `(r - 1) // n + 1` |

1부터 세면서 경우를 나누어 계산해도 된다. `r % n == 0`이면 번호는 `n`, 차례는 `r // n`이다. 나머지가 있으면 번호는 `r % n`, 차례는 `r // n + 1`이다.

예를 들어 3명 중 전체 5번째 발언은 2번 사람의 2번째 차례다. 잘못된 식 `5 // 3 + 5 % 3`은 `3`이 되지만, 올바른 식 `5 // 3 + 1`은 `2`가 된다.

#### 내 풀이 구조를 유지한 수정본

```python
def solution(n, words):
    result = 0

    for i, value in enumerate(words):
        if i >= 1:
            if value[0] != words[i - 1][-1]:
                result = i
                break

            for j in range(i):
                if value == words[j]:
                    result = i
                    break

            # 중복을 찾았다면 바깥 반복문도 종료한다.
            if result != 0:
                break

    if result != 0:
        return [result % n + 1, result // n + 1]

    return [0, 0]
```

이 문제는 단어 길이가 2 이상으로 주어져 첫 단어로 탈락할 수 없다. 따라서 `result = 0`을 탈락자 없음으로 사용할 수 있다.

**기억할 규칙:** `break`는 가장 가까운 반복문 하나만 끝낸다. 최초의 실패를 찾는 문제에서는 찾은 뒤 전체 탐색을 멈춘다. 번호는 나머지로, 차례는 몫으로 계산하되 0부터 세는지 1부터 세는지 확인한다.

### ❌ 03 · 오픈채팅방 — 닉네임 관리와 입퇴장 기록 분리

- 학습 상태: **풀이 참고 · 재풀이 필요**
- 제출 상태: 통과 여부 미확인. 수정본을 참고했으므로 혼자 해결한 문제로 기록하지 않는다.
- 문제: 입장·퇴장 메시지를 각 사용자의 최종 닉네임으로 출력한다. 닉네임 변경 자체는 메시지를 남기지 않는다.
- 내가 시도한 방법: 기록을 공백으로 나누고, `Enter`·`Leave`·`Change`별로 처리했다. `log`에 행동·ID·닉네임을 함께 저장하고 마지막에 메시지를 만들었다.

#### 실수와 원인

| 실수하거나 막힌 부분 | 원인과 수정 방향 |
| --- | --- |
| 모든 기록에서 `values[2]`에 접근 | `Leave`에는 행동과 ID만 있어 닉네임 위치가 없다. 기록 종류에 따라 접근할 위치를 구분한다. |
| 기존 ID가 있으면 입장 기록을 추가하지 않음 | 재입장도 새로운 입장이다. 닉네임 수정과 입장 기록 추가를 별개로 처리한다. |
| 닉네임 수정 후 `break`로 종료 | 같은 ID의 첫 기록만 수정된다. 모든 과거 메시지에도 최종 닉네임이 적용되어야 한다. |
| `for i, j, k in log`에서 `k = 새이름`으로 수정 | 변수 `k`에 새 문자열을 대입해도 원래 리스트의 원소는 바뀌지 않는다. 기존 구조에서는 `logs[2]`에 직접 대입해야 한다. |
| `Leave`에 넣을 닉네임을 찾으려 함 | 각 기록에 닉네임까지 저장하니 이름을 찾거나 과거 기록을 수정하는 작업이 반복된다. ID와 최종 닉네임을 따로 관리한다. |

`[[]]`로 시작해 불필요한 빈 행이 생기는 내용은 [기초편](./기초편.md)의 리스트 관련 기록을 함께 참고한다.

#### 개선 방향 · 직접 구현할 내용

- `log`에는 입장·퇴장 행동과 사용자 ID만 순서대로 저장한다.
- 딕셔너리에는 사용자 ID를 키로, 최종 닉네임을 값으로 저장한다.
- `Enter`와 `Change`에서 딕셔너리의 닉네임을 갱신한다.
- `Enter`와 `Leave`는 로그에 추가하고, `Change`는 메시지용 로그에 추가하지 않는다.
- 모든 기록을 처리한 뒤 로그를 순회하며 딕셔너리에서 최종 닉네임을 가져와 메시지를 만든다.

이전에 참고한 수정본은 매번 과거 로그를 검색하거나 수정하므로 기록 수가 많으면 시간 초과가 날 수 있다. 딕셔너리 방식은 과거 로그를 반복해서 고칠 필요가 없다.

**기억할 규칙:** 발생한 사건의 순서와 나중에 바뀔 수 있는 사용자 정보를 분리해서 저장한다.

#### 재풀이 확인 사항

- [ ] 완성 코드를 보지 않고 딕셔너리 방식으로 직접 작성하기
- [ ] 퇴장 후 다른 닉네임으로 재입장해도 모든 메시지에 최종 이름이 반영되는지 확인하기
- [ ] 닉네임 변경 자체에는 메시지가 생기지 않는지 확인하기
- [ ] 서로 다른 ID가 같은 닉네임을 사용해도 구분되는지 확인하기
- [ ] 직접 제출한 결과를 확인한 뒤 제출 상태 갱신하기
